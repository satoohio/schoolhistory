## Обзор проекта

Сайт создан для школы №1 и включает:

- **Фотогалерею** с masonry-сеткой, фильтрацией по категориям, поиском и лайтбоксом
- **Регистрацию и вход** с JWT-токенами и хешированием паролей через bcrypt
- **Административную панель** для управления фотографиями, категориями, пользователями и текстовым контентом страниц
- **Адаптивный дизайн** для корректного отображения на мобильных устройствах, планшетах и ПК

## Установка и запуск

### Требования

- Node.js 20+
- PostgreSQL 16+

### 1. Клонирование репозитория

```bash
git clone https://github.com/satoohio/schoolhistory.git
cd schoolhistory
```

### 2. Установка зависимостей

```bash
npm install
```

### 3. Настройка переменных окружения

Создайте файл `.env` в корне проекта (см. раздел [Переменные окружения](#переменные-окружения)).

### 4. Инициализация базы данных

```bash
node server/db.js
```

> При первом запуске автоматически создаются таблицы, категории по умолчанию, контентные страницы и учётная запись администратора.

### 5. Запуск в режиме разработки

```bash
npm run dev
```

Запускает одновременно:
- **Backend** — `http://localhost:3001`
- **Frontend** — `http://localhost:5000`

### 6. Сборка для production

```bash
npm run build
node server/index.js
```

Express раздаёт `dist/` как статику и обрабатывает API-запросы.

## Переменные окружения

Создайте файл `.env` в корне проекта:

```env
# Строка подключения к PostgreSQL (обязательно)
DATABASE_URL=postgresql://user:password@localhost:5432/schoolhistory

# Секрет для подписи JWT (обязательно, замените на случайную строку)
JWT_SECRET=your_very_secret_key_here

# Порт API-сервера (необязательно, по умолчанию 3001)
API_PORT=3001

# Окружение (влияет на SSL-настройки PostgreSQL)
NODE_ENV=development
```

> В production при `NODE_ENV=production` SSL для PostgreSQL включается автоматически.

## API — справочник эндпоинтов

Базовый URL: `http://localhost:3001/api`

Для защищённых маршрутов передавайте заголовок:
```
Authorization: Bearer <JWT_TOKEN>
```

### Аутентификация `/api/auth`

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| `POST` | `/auth/register` | Публичный | Регистрация нового пользователя |
| `POST` | `/auth/login` | Публичный | Вход, возвращает JWT |
| `GET` | `/auth/me` | Авторизован | Данные текущего пользователя |

**POST /auth/register** — тело запроса:
```json
{
  "name": "Иван Иванов",
  "email": "ivan@example.ru",
  "password": "minLength6"
}
```

**POST /auth/login** — тело запроса:
```json
{
  "email": "ivan@example.ru",
  "password": "password123"
}
```

Оба эндпоинта возвращают:
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": { "id": 1, "name": "Иван", "email": "ivan@example.ru", "role": "user" }
}
```

### Администрирование `/api/admin`

Все маршруты требуют JWT-токен с ролью `admin`.

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/admin/stats` | Общая статистика (кол-во пользователей, фото, категорий) |
| `GET` | `/admin/users` | Список всех пользователей |
| `PATCH` | `/admin/users/:id/role` | Изменить роль пользователя |
| `POST` | `/admin/categories` | Создать новую категорию |
| `DELETE` | `/admin/categories/:id` | Удалить категорию |

**PATCH /admin/users/:id/role** — тело запроса:
```json
{ "role": "admin" }
```
> Нельзя изменить роль самому себе.

**POST /admin/categories** — тело запроса:
```json
{
  "name": "Экскурсии",
  "slug": "excursions"
}
```
> `slug` должен быть уникальным, только латиница и дефис.

## Страницы сайта

### Главная (`/`)
- Hero-секция с градиентным фоном и анимацией появления
- Блок статистики: ученики, учителя, награды, лет истории
- Сетка избранных фотографий (до 6 штук, помечены `is_featured = true`)
- CTA-блок с призывом к регистрации

### Галерея (`/gallery`)
- Masonry-сетка фотографий (2–4 колонки в зависимости от ширины экрана)
- Фильтрация по категориям (pill-кнопки, активная подсвечивается синим)
- Поиск по названию и описанию (клиентская фильтрация в реальном времени)
- Счётчик найденных фотографий
- Лайтбокс: просмотр в полном размере, навигация стрелками ← →, закрытие по Escape или клику вне области

### О школе (`/about`)
- Текстовый блок с историей школы (контент редактируется через админ-панель)
- Карточки ценностей: Знания, Команда, Достижения, Забота

### Контакты (`/contacts`)
- Карточки с контактными данными: адрес, телефон, email, режим работы
- Форма обратной связи (имя, email, сообщение)

### Вход (`/login`)
- Форма с полями email и пароль
- Кнопка переключения видимости пароля
- Сообщение об ошибке при неверных данных
- После входа: обычный пользователь → `/`, администратор → `/admin`

### Регистрация (`/register`)
- Форма с именем, email, паролем и подтверждением пароля
- Валидация: минимум 6 символов, совпадение паролей
- Автоматический вход после успешной регистрации

## Административная панель

Маршрут: `/admin` — доступен только пользователям с ролью `admin`.

### Вкладка «Фотографии»
- Просмотр всех загруженных фотографий в сетке 4 колонки
- При наведении появляются кнопки управления:
  - **★** — добавить/убрать из избранного (показ на главной странице)
  - **🗑** — удалить фото (файл физически удаляется с диска)
- Кнопка «Добавить» переводит на вкладку загрузки

### Вкладка «Загрузить»
- Drag-and-drop зона или клик для выбора файла
- Предпросмотр выбранного изображения с кнопкой очистки
- Поля: название (обязательно), категория (выпадающий список), описание
- Переключатель «Показать на главной странице»
- После загрузки автоматически переходит на вкладку «Фотографии»

### Вкладка «Категории»
- Список всех категорий с названием, slug и количеством фото
- Форма добавления: название + slug (автоматически очищается от спецсимволов)
- Кнопка удаления каждой категории

### Вкладка «Пользователи»
- Полный список зарегистрированных пользователей с аватаром-инициалом
- Badge роли: **Админ** (синий) / **Пользователь** (серый)
- Кнопка «Сделать админом» / «Разжаловать» (недоступна для себя)

### Вкладка «Страницы»
- Редактирование контента страниц «О школе» и «Контакты»
- Отдельная карточка для каждой страницы с полями: заголовок и текст
- Кнопка «Сохранить изменения» для каждой страницы

## Система авторизации

### Роли пользователей

| Роль | Возможности |
|---|---|
| `user` | Просмотр всех публичных страниц и галереи |
| `admin` | Всё что `user` + доступ к `/admin`, загрузка/удаление фото, управление контентом |

### Как работает JWT

1. При регистрации или входе сервер создаёт JWT с полезной нагрузкой:
   ```json
   { "id": 1, "email": "...", "role": "admin", "name": "..." }
   ```
2. Токен действует **7 дней**
3. Frontend сохраняет токен в `localStorage`
4. Функция `authFetch` из `AuthContext` автоматически добавляет заголовок `Authorization: Bearer <token>` ко всем запросам
5. Middleware `authenticateToken` верифицирует токен при каждом запросе и кладёт данные в `req.user`
6. Middleware `requireAdmin` проверяет `req.user.role === 'admin'` — иначе 403

### Использование AuthContext в компонентах

```jsx
import { useAuth } from '../context/AuthContext'

function MyComponent() {
  const { user, isAdmin, login, logout, authFetch } = useAuth()

  // user        — объект пользователя или null
  // isAdmin     — boolean
  // login(token, userData) — сохраняет токен, обновляет состояние
  // logout()               — очищает токен и состояние
  // authFetch(url, opts)   — fetch с автоматическим JWT-заголовком
}
```

## Загрузка файлов

Файлы сохраняются в папку `uploads/` в корне проекта (создаётся автоматически).

### Ограничения
- **Максимальный размер**: 10 МБ на файл
- **Допустимые форматы**: JPEG, JPG, PNG, GIF, WebP
- **Именование файлов**: `{timestamp}-{random}.{ext}` — исключает коллизии имён

### Доступ к файлам
Express раздаёт папку `uploads/` как статику:
```
GET /uploads/1748123456789-987654321.jpg
```

Vite-прокси в dev-режиме перенаправляет `/uploads/*` → `http://localhost:3001`.

### Удаление
При удалении фото через API (`DELETE /photos/:id`) файл физически удаляется с диска через `fs.unlinkSync`.
